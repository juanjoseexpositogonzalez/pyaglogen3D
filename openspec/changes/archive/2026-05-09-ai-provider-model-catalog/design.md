# Design: AI Provider Model Catalog

## Technical Approach

Add `model_catalog.py` service with per-provider SDK fetchers, whitelist filtering, and recommended-model heuristics. Augment `test_connection` to also fetch catalog on success. New `refresh_models` action for on-demand re-fetch. Frontend replaces hardcoded `PROVIDERS[].models` arrays with dynamic `available_models` from API response.

## Architecture Decisions

| Decision | Alternatives | Rationale |
|----------|-------------|-----------|
| Standalone `model_catalog.py` module (not in provider classes) | Add `list_models()` to each provider class | Catalog logic is cross-cutting (whitelist, recommend, normalize). Providers handle completions; catalog is a separate concern. Avoids polluting the provider interface. |
| Typed exceptions (`ProviderAuthError` etc.) | Re-raise SDK exceptions directly | Callers map to HTTP status codes. Typed exceptions decouple view layer from SDK internals. Define in `model_catalog.py` (3 classes, all extend `Exception`). |
| JSONField on `AIProviderConfig` (not separate table) | `AIModel` FK table | No query patterns justify a separate table. Models are a cached snapshot, not relational data. JSONField keeps migration trivial and reversible. |
| Reuse `openai.OpenAI` for Groq/xAI | Per-provider SDK packages | Already works this way in the codebase (`GroqProvider`/`XAIProvider` extend `OpenAIProvider` with custom `base_url`). Catalog fetcher mirrors this pattern. |
| No caching / TTL | Redis cache per provider | Fetches are user-triggered only (test/refresh). Extra infra not justified for <1 req/min/user. |

## Data Flow

```
User clicks "Test Connection"
        │
        ▼
  AIProviderConfigViewSet.test_connection()
        │
        ├── 1. decrypt(api_key_encrypted)
        ├── 2. ProviderFactory.create_from_config() → provider.complete() [auth test]
        │       │ fail → return 400 (no catalog change)
        │       │ pass ↓
        ├── 3. fetch_models(provider_name, api_key) ← model_catalog.py
        │       │ SDK.models.list() → whitelist → recommend → normalize
        │       │ fail → log warning, models=None (auth still passed)
        │       │ pass ↓
        ├── 4. config.available_models = result
        │      config.models_refreshed_at = now()
        │      config.save()
        └── 5. Response { success, message, models, refreshed_at }
                    │
                    ▼
           Frontend updates <select> from models[]
```

## Testing Strategy

| Layer | What | Approach |
|-------|------|----------|
| Unit | `fetch_models` per provider | Mock `anthropic.Anthropic` and `openai.OpenAI`; assert whitelist filtering, recommended marker, error mapping |
| Unit | `normalize_display_name` | Pure function — parametrized test with known id→name pairs |
| Integration | `test_connection` with catalog | Mock SDK at `model_catalog.fetch_models` level; assert DB has `available_models` populated; assert response shape |
| Integration | `refresh_models` endpoint | Same mock strategy; assert 401/503/429 mapping from typed exceptions |
| Frontend | Select/CTA/badge/warning | Vitest — mock `aiApi` responses; assert renders |

Run: `backend/.venv/bin/pytest backend/apps/ai_assistant/tests/`

## Migration / Rollout

- Migration `0004`: `AddField(available_models, JSONField, default=list)` + `AddField(models_refreshed_at, DateTimeField, null=True)`. Fully reversible via `RemoveField`.
- No data backfill — existing configs start with `[]` / `null`.
- No feature flag needed — empty catalog degrades gracefully to CTA.
- Rollback: `python manage.py migrate ai_assistant 0003` + revert merge commit.
